# 配信枠レイアウトのカスタマイズ — 要件定義

作成: 2026-08-25 / 状態: **実装・レビュー完了 (2026-08-25, v1.0.2)**

`tasks/todo.md` の「デザイン 4」から分離。実装したら `docs/SPEC.md` に移し、

## 0. 背景

過去に実装を試みてエラーが多発し断念した経緯がある。原因はおそらく
**設計思想4（iframe を壊さない）との衝突**なので、そこを最初に固定する。

---

## 1. 絶対制約

> **DOM の構造と順序を変えず、CSS のプロパティだけで表現できる範囲に収める。**

DOM ノードが物理的に移動すると、ブラウザが iframe を再読み込みする。
並べ替えで踏んだのと同じ罠（`docs/SPEC.md` 4章）。

| やること | 手段 | 判定 |
|---|---|---|
| 枠の大きさを変える | セルの `grid-column` / `grid-row` | ✅ 安全 |
| 境界を動かす | `grid-template-columns` の `fr` 値 | ✅ 安全 |
| 1枠を全画面に | `grid-area: 1 / 1 / -1 / -1` + 他を `display:none` | ✅ 安全 |
| 入れ子で領域分割 | セルごとに親要素を追加 | ❌ **DOM が変わる** |
| リサイズハンドルをセル間に差し込む | セルの兄弟として挿入 | ❌ **セルが移動する** |

**入れ子の領域分割は採用しない。** フラットな CSS Grid 1枚で表現できる
レイアウトだけを対象にする。これが機能の上限を決める。

---

## 2. 決定事項

ユーザー判断済み (2026-08-25)。

| 論点 | 決定 |
|---|---|
| 自由度 | **テンプレート選択 ＋ 境界ドラッグ** |
| 拡大中の他枠の音声 | **流れ続ける**（`display:none` で隠すだけ。復帰時にリロードしない） |
| 保存範囲 | **localStorage のみ**。共有コードには含めない（v2 の互換を壊さない） |

## 3. データモデル

```ts
/** グリッド上の1区画。1-based のグリッド線番号で表す */
interface Slot {
    col: number;      // 開始列
    row: number;      // 開始行
    colSpan: number;
    rowSpan: number;
}

/** 枠数から実際の配置を組み立てた結果 */
interface ResolvedLayout {
    colTracks: number[];   // 列の fr 値。境界ドラッグはこの配列を書き換える
    rowTracks: number[];
    slots: Slot[];         // 長さは必ず枠数と一致させること（下記参照）
}

type TemplateId = 'auto' | 'main-left' | 'main-right' | 'main-top';

/** localStorage に保存する状態。枠数ごとに独立して持つ */
interface LayoutState {
    templateId: TemplateId;
    /** 境界ドラッグの結果。テンプレートを変えたら破棄する */
    tracks?: { cols: number[]; rows: number[] };   // fr 値
}

type LayoutStore = Record<number, LayoutState>;    // キーは枠数
```

**`slots.length` は必ず枠数と一致させる。** 足りないとセルが自動配置に
落ちて意図しない位置に飛び、多いと使われないスロットが残る。
`buildLayout()` の事後条件としてテストで固定する。

## 4. テンプレート

枠数ごとに定義を並べるのではなく、**枠数から生成する**。
そうしないと枠数が増えるたびに定義が増え、破綻する。

| id | 内容 | 適用条件 |
|---|---|---|
| `auto` | 現状の `calcOptimalGrid()`。等分 | 常に（既定） |
| `main-left` | 左に大きい1枠、右に残りを縦1列 | 2枠以上 |
| `main-right` | 右に大きい1枠、左に残りを縦1列 | 2枠以上 |
| `main-top` | 上に大きい1枠、下に残りを横1列 | 2枠以上 |

`main-*` は「メイン1 + 残り n」なので**任意の枠数で成立する**。
メインの占有幅は既定でサブ列の2倍（境界ドラッグで変更可）。

拡大（ダブルクリック）は**テンプレートではなく一時状態**として扱う。
選択中のテンプレートを保持したまま上書きし、解除で元に戻る。

## 5. レンダリング

`StreamGrid` の変更点。

### 5.1 明示配置に切り替える

```tsx
// 現在: 自動配置 + order
style={{ order: visualIndex }}

// 変更後: 明示配置（order は不要になる）
style={{
    gridColumn: `${slot.col} / span ${slot.colSpan}`,
    gridRow:    `${slot.row} / span ${slot.rowSpan}`,
}}
```

`domSeq` による DOM 順序の固定は**そのまま維持する**。
明示配置は「どこに描くか」だけを決め、DOM 上の並びには関与しない。
`visualIndex`（配列順）が何番目のスロットに入るかを決める。

**「どの配信をメイン枠に置くか」は既存のドラッグ入れ替えで既に解決している。**
配列の先頭に来た配信がスロット0＝メインに入る。新しい操作は足さない（設計思想7）。

### 5.2 拡大を同じツリーで表現する

現在は別ツリーを返しており、これが「拡大／復帰で全枠リロード」の原因。

```tsx
// 拡大中のセル
{ gridArea: '1 / 1 / -1 / -1' }
// それ以外のセル
{ display: 'none' }
```

`display:none` は iframe を破棄しないので、復帰時にリロードされない。
**代償として、隠れている配信の音声は鳴り続ける**（決定事項のとおり許容）。

全画面時の余白は `.stream-grid-container` にクラスを足して `padding: 0` にする。
要素そのものは同じなので安全。

## 6. 境界ドラッグ

### 6.1 ハンドルの置き場所（重要）

**ハンドルをセルの兄弟として差し込んではいけない。** セル間に DOM ノードが
入ると、React がセルを `insertBefore` で動かし、iframe がリロードされる。

> **グリッドの上に敷いた `position: absolute` のオーバーレイ層に置き、
> 常にすべてのセルより後ろ（最後）に描画する。**

末尾への追加ならセルは動かない。ハンドルの座標は `cols` / `rows` の
`fr` 値から計算する。

### 6.2 挙動

- 既定では**見えない**。グリッドにホバーしたときだけ薄く出す（設計思想1）
- ドラッグ中は既存の `drag-global-overlay` と同じ全画面オーバーレイで
  iframe のイベント奪取を防ぐ
- ドラッグ結果は `fr` 値の配列として保存する
- **最小幅を設ける**（`0.3fr` 程度）。0 にできると枠が消えて復帰不能になる
- テンプレートを切り替えたら `tracks` は破棄する（列数・行数が変わるため）

### 6.3 アスペクト比

**16:9 は保証しない。** 現状も保証していない（`calcOptimalGrid` は近似するだけで、
セルは `1fr` で引き伸ばされる）。埋め込み側がレターボックスするので破綻はしない。

## 7. 永続化

- キー: `streamLayouts`
- 値: `LayoutStore`（枠数ごとの `LayoutState`）
- 枠数が変わったら、その枠数に保存された状態を使う。無ければ `auto`

枠数ごとに持つのは、4枠→5枠→4枠と戻ったときに設定が復元されるため。
共有コードには含めない（決定事項）。

## 8. UI 導線 — 決定済み (2026-08-25)

**配信管理パネルの上段。** パネルを「上段=見え方 / 下段=配信の管理」の
2段構成にする（ユーザー判断）。

当初はヘッダーを推していたが、レイアウトの選択と配信の並べ替えは
**続けて行う操作**なので、同じパネル内にある方がマウスの移動が短い。
どの配信をメインに置くかは下段のドラッグで決めるため、上下に並ぶのが自然。

2枠未満では `main-*` が成立しないので、上段そのものを出さない。

### レビューの結論 (2026-08-25)

すべて実機で確認済み。回帰なし。

- **`main-left` / `main-right` は残す。** 「あっても無くても良い」という評価だが、
  維持コストが無いため
- **メイン:サブの既定比率 `MAIN_RATIO = 2` は妥当**
- **境界ドラッグは残すが、位置づけは補助。**
  ユーザー評価は「レイアウト機能が均等に最適な表示をしてくれるので、
  リサイズはほぼ不要」。とくに L字は枠数から自動で 16:9 に近い配置を出すため、
  手で調整する必要がほとんど無い。
  削除する理由も無いので現状維持とするが、**今後この機能まわりで
  複雑さが増すようなら、真っ先に削除を検討してよい**（設計思想7）

### 追加したもの（当初の要件に無かった）

- **L字レイアウト**（左上 / 右上）。枠数を縦横に振り分けるだけで決まり、
  偶数枠ではメインもサブも正確に 16:9 になる。これが実質の主役になった
- ハンドルを「実際に枠の境目になっている区間」だけに描く仕組み

## 10. テスト方針

純粋関数に切り出せる部分をすべてテストする。
`tasks/todo.md` の方針どおり、**わざと壊して落ちることを確認**すること。

| 対象 | 守るもの |
|---|---|
| `buildLayout(templateId, count)` | `slots.length === count`、範囲外のスロットが無いこと |
| `buildLayout` の `main-*` | メインが2マス以上を占め、サブが重ならないこと |
| `clampTracks(fr[], min)` | 最小値を下回らない、合計が保存される |
| `loadLayoutStore` / 不正JSON | 壊れた localStorage で `auto` に落ちること |

**リロードが起きないこと自体は自動テストでは守れない。**
jsdom は iframe を実際に読み込まないため。実装の各段階で
**実機での目視確認を必須**とする（9枠で拡大→復帰、テンプレート切替、境界ドラッグ）。
