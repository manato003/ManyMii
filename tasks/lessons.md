## 2026-02-23

### fflateインストール時にnode_modulesが破損した
- **状況**: `npm install fflate` 実行後にViteの依存関係が大量に消えてホワイトアウト
- **原因**: OneDrive上のプロジェクトでnpmがファイルロックを正しく処理できなかった
- **教訓**: 新しいnpmパッケージを追加する前にdevサーバーを停止する。OneDrive環境では特に注意。
- **対策**: パッケージ追加時は `Ctrl+C` でサーバー停止 → インストール → サーバー再起動の順で行う

### ドラッグ時に全フレームがリロードされるバグ
- **状況**: 枠の入れ替え時に全配信がリロードされる
- **原因**: StreamGridで `reloadKeys` をstateで管理し、StreamFrameの `key` に含めていたため並び替えで全フレームが再マウント
- **教訓**: `key` に含める値が変化すると対象コンポーネントが完全に再マウントされる。リロードキーはStreamFrame内部stateで管理する。
- **対策**: StreamFrameの `key={stream.id}` のみ。reloadKeyはStreamFrame内部で管理してplayerコンポーネントにだけ渡す。

### ドロップダウン外クリックで閉じる実装が配信画面に干渉
- **状況**: 設定ドロップダウンの「外クリックで閉じる」がiframe（配信画面）のクリックでも発火して再生が止まる
- **原因**: `mousedown` イベントリスナーをdocumentに貼っていた
- **教訓**: iframeの外でのクリックが意図せず配信に影響する場合がある
- **対策**: 外クリック閉じを削除。閉じる方法はマウスアウト or ハンバーガー再クリックのみ

### @handleがTwitchとして処理されるバグ
- **状況**: `@Popo_Ieiri` を入力すると `/embed/@Popo_Ieiri` になり再生エラー
- **原因**: `detectPlatformFromUrl` に `@` 形式の処理がなく、デフォルト（Twitch）が使われた
- **対策**: `detectPlatformFromUrl` に `@` で始まる入力をYouTubeとして扱うケースを追加

### React.memoへの書き換えで};と});が二重になるバグ
- **状況**: `React.memo` でラップする際、末尾の `};` を削除せず `});` を追加して構文エラー
- **対策**: 末尾の `};` を `});` に**置換**する（追加ではなく置換）

## 2026-08-25（v1.0.0 〜 v1.0.2）

### 報告した修正が実際にはコミットされていなかった
- **状況**: 「ペーストボタンを枠線だけのボタンにした」と報告したが、`.paste-btn` の
  CSS はリポジトリに入っておらず、本番ではブラウザ既定のボタンのまま出ていた
- **原因**: 変異テスト中に `cp バックアップ 元ファイル` でファイルを戻した際、
  同じ作業で入れた別ファイルの編集まで巻き添えで失われた
- **なぜ気づけなかったか**: `.paste-btn` は DOM 上のクラス名としては存在するため
  テストは通る。CSS が当たっているかはテストで検出できない
- **対策**: 一連の編集を報告する前に `git diff --stat` と `grep` で
  **実際にその変更が入っているかを確認する**。ビルド後のハッシュ照合まで通す

### 状態の保存キーは「ユーザー操作で変わらない軸」を選ぶ
- **状況**: レイアウトを「枠数ごと」に保存したら、枠を1つ非表示にしただけで
  設定が既定に戻った（6枠→5枠でキーが変わり未設定になる）
- **教訓**: 保存の粒度を決めるときは「そのキーが日常操作で変わるか」を先に問う
- **対策**: テンプレートは全体で1つ、トラック幅（列数・行数に依存する値）だけ
  枠数ごとに持つ。**依存があるものだけを細かく持つ**

### 拡大表示で別のツリーを返してはいけない
- **状況**: `if (expandedId) return <別のJSX>` としていたため、拡大するたびに
  対象以外の `StreamFrame` がアンマウントされ、復帰時に全枠がリロードされた
- **対策**: 同じツリーのまま、対象セルを `grid-area: 1/1/-1/-1`、他を
  `display: none` にする。`display:none` は iframe を破棄しない
- **代償**: 隠れた枠の音声は鳴り続ける。仕様として受け入れた

### リサイズハンドルはセルの兄弟にも、全長にも引かない
- **セル間に差し込まない**: DOM ノードがセル間に入ると React が
  `insertBefore` でセルを動かし、iframe がリロードされる。
  絶対配置のレイヤに置き、必ず全セルより後ろに描く
- **全長に引かない**: L字ではグリッド線の多くがメイン枠の内側を通っており、
  全長に引くと映像の上を線が縦断するうえ、掴んでも別の枠しか動かない。
  「両隣のマスが違う枠に属している区間」だけを描く

### リサイズの影響を隣1本で吸収させると破綻する
- **状況**: 境界を動かすと隣のトラックだけが極端に潰れ、他は不動だった
- **対策**: 境界の左右それぞれの**全トラックに比例配分**する。
  各側は元の比率を保ったまま伸縮するので、意図的な大小関係が壊れない

### レイアウトは「枠数ごとの定義表」を持たない
- **教訓**: 枠数ごとに定義を並べると、枠が増えるたびに定義が増えて破綻する
- **対策**: 枠数から生成する。L字は `列数 + 行数 = 枠数` の組を総当たりし、
  メインとサブの縦横比が 16:9 に最も近い組を選ぶ。**定数は持たない**
- **副産物**: 16:9 の画面では列数 = 行数のとき黒帯が完全に消える

### Vercel はプロジェクト改名後も旧ドメインを保持していた
- **状況**: 「改名すると公開URLが変わり共有リンクが切れる」と警告したが、
  実際には旧 `.vercel.app` ドメインが割り当てられたまま残っていた
- **教訓**: 外部サービスの挙動は**実測してから断定する**。
  ただし「切れる前提」で伝えたこと自体は安全側で正しい
- **注意**: 旧ドメインは削除せず、新URLへの Redirect に変えると上位互換

### CSS で「反対側を 0 にリセット」すると同じ詳細度の相手を打ち消す
- **状況**: 両方のサイドパネルをピン留めすると片側ぶんしか本体が狭まらない
  （パネル左右入れ替え時のみ発生）
- **原因**: 入れ替え用の2ルールが互いに反対側を `padding-*: 0` でリセットしていた。
  詳細度が同じなので後に書かれた方が勝ち、先のルールの余白が消える

  ```css
  .app-main.chat-pinned.panels-swapped   { padding-right: 0; padding-left:  chat; }
  .app-main.stream-pinned.panels-swapped { padding-left:  0; padding-right: stream; }
  /* 両方付くと padding-left: 0 が勝ってチャット側の余白が消える */
  ```

- **対策**: 各ルールは**自分がいる側だけ**を指定し、反対側に触れない。
  通常配置と入れ替え配置は `:not()` で排他にする
- **教訓**: 複数の独立した条件が同じ要素のスタイルを決めるときは、
  **条件ごとに別のプロパティだけを触る**。リセットを書いた時点で結合してしまう

### スタイルシートのカスケードはテストで守れる
- **状況**: 上のバグはロジックが一切絡まないので、純粋関数テストでも
  コンポーネントテストでも検出できなかった
- **対策**: jsdom に実際の CSS を流し込み `getComputedStyle` で計算値を見る。
  **Vitest は既定で CSS をスタブ化する**ので `test.css: true` が要る
  （これが無いと `?raw` が空文字になる）
- jsdom は `var()` を解決しないので、値ではなく**どの変数が使われているか**で判定する

### ツリーのドロップ先は「行の中のどこか」で決める
- **状況**: フォルダ内の要素を上位の階層へ移動できなかった
- **原因1**: ドロップ処理に `moveNode(id, null)`（ルートへ移動）を呼ぶ枝が無く、
  ルートを指すドロップ先も UI に存在しなかった
- **原因2**: 親をまたぐドロップが `reorderInTree` に流れていたが、この関数は
  from と to が**同じ配列にあるときだけ**動く。違う親だと無変化で返り、
  ユーザーには「効かない」としか見えなかった
- **対策**: 行を上端/中央/下端の3つに分け、上下端は「前後に挿入」にした。
  これで**ルート直下の項目の前後に落とすだけで階層が上がる**。
  専用のドロップ先を作らなくても階層移動が成立する
- **教訓**: ツリーUIで「入れ子にする」操作しか用意しないと、**外に出す操作が消える**。
  入れ子と並べ替えは対で設計する

### ドラッグ状態を再帰コンポーネントの各階層で持たない
- **状況**: `FavoritesTree` が自分自身を再帰描画しており、各インスタンスが
  独自のドラッグ state を持っていた。そのためドロップ先のハイライトが
  ドラッグを開始した階層の中でしか出なかった
- **対策**: ルートだけが state を持ち、各階層へ props で配る

### ハイライトの判定と実際の移動で同じ関数を使う
- **教訓**: 「光ったのにドロップしても動かない」は原因が見えず一番たちが悪い
- **対策**: 可否判定を `canMoveInto` に切り出し、見た目と実行の両方から呼ぶ
