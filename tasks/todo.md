## ライブ解決の方式（2026-08-23 解決済み）

実プロキシ調査の結論と、採用した方式。

**判明したこと**: YouTubeはデータセンターIPからのリクエストに対し、200 を返しながら
中身のないページを返す（canonical="undefined"、ytInitialData なし）。
そのため素のCORSプロキシによる /live スクレイピングは**そもそも機能していなかった**。
従来これは「オフライン」と誤表示されていた。

**採用**: r.jina.ai に X-Return-Format: html でチャンネルページを取らせる方式
（詳細は docs/SPEC.md 3章）。1リクエストでライブID・チャンネル名・チャンネルIDが揃う。

**残るリスク**:

- **r.jina.ai への依存**。無料枠にレート制限があり、連続で叩くと HTTP 429 になる
  （調査中に実際に到達した）。落ちたときは /live 経路にフォールバックするが、
  そちらの成功率は低いので「取得失敗」表示になる。
  **緩和済み (2026-08-24)**: 解決結果を localStorage にキャッシュし、リロードや
  同一チャンネルの再追加でリクエストが飛ばないようにした（docs/SPEC.md 3章）。
  依存自体は消えていない
- **応答サイズが 1.2〜2.7MB**。オフライン枠5つを5分ごとに再確認すると
  1時間あたり100MB超になるため、自動再確認は既定OFFにした (2026-08-23)
- **視聴対象が第三者サービスに渡る**（他のCORSプロキシと同じ性質）
- ytInitialData の構造に依存しているため、YouTube側の変更で壊れうる。
  壊れたときは「オフライン」ではなく「取得失敗」と出る導線は実装済み
- 配信中でも「注目コンテンツ」に別の動画を固定しているチャンネルでは
  ライブを拾えない可能性がある（未確認）

### 1. YouTubeチャンネルのライブID解決ロジックの修正 — 対応済み (2026-08-23)

調査で判明していた欠陥はすべて対応済み。方式そのものについては上記を参照。

- **/channel/UCxxxx 形式のURLが壊れていた** — 全分岐をすり抜けてURL全体を video ID として
  扱い、embed/https://... という不正なURLを生成していた
- **/c/name, /user/name の旧形式が未対応だった**
- **ハンドル抽出が [a-zA-Z0-9_-]+ で狭かった** — ピリオドや非ASCIIを含むハンドル
  （@name.official, @ぽぽ）がURLからは取れなかった
- **タイムアウトがなかった** — 死んだプロキシの応答に20秒以上かかり全体が固まっていた。
  1リクエスト6秒（レンダリング経路は15秒）で打ち切る
- **縮退ページを「オフライン」と誤判定していた** — 検出して「取得失敗」に分類

テスト対応済み (2026-08-23)。

### 3. 配信管理パネルにチャンネル名を表示する — 実装済み (2026-08-23)

以下は残課題。

- Twitchの表示名取得は追加のプロキシリクエストが1回発生する。
  取得できなければログイン名のままなので実害はないが、プロキシが不調だと名前が出ない
- 既にお気に入り・履歴に入っている項目は、その配信を一度追加し直すまで
  表示名が埋まらない（`propagateDisplayName` が走るのが解決時のため）

<details><summary>当初の課題メモ</summary>

現状パネルに出ているのは表示名ではなく識別子。

| 種別 | 現在の表示 | 出したいもの |
|---|---|---|
| YouTube（ハンドル追加） | `@Popo_Ieiri` | チャンネルの表示名 |
| YouTube（動画URL追加） | 11桁の video ID（ハンドル解決後は `@handle`） | 同上 |
| Twitch | ログイン名（`tototmix`） | 表示名（`ととみっくす` 等） |

`Stream.title` にそのまま識別子を入れているのが原因
（`buildStream()` と `parseInput.ts` の `title`）。

実装方針:
- YouTube: 既に `/live` ページと watch ページの HTML を取得しているので、
  同じレスポンスから表示名も抜き出せる（`"author"` や `og:title` 等）。
  追加のリクエストは不要。
- Twitch: 現状スクレイピングを一切していないため、表示名の取得には
  `twitch.tv/<login>` の HTML 取得が新たに必要になる。
  APIキーは使わない方針（CLAUDE.md 設計思想3）なのでプロキシ経由になる。
- `Stream` に `displayName?: string` を追加し、パネル・枠ヘッダー・コメント
  セレクターの表示はそれを優先、未取得なら現在の `title` にフォールバックする。
- 取得できなかった場合に識別子へ戻る挙動を必ず用意すること。
</details>

### 2. 履歴フィールドの削除ボタンを赤いゴミ箱に変える — 実装済み (2026-08-24)

`StreamSidePanel` で、意味の違う操作に同じ `X` アイコンを使ってしまっている。

| フィールド | 現在 | 意味 | あるべき姿 |
|---|---|---|---|

### 3. 配信追加モーダルにペーストボタンを追加 — 実装済み (2026-08-24)

`AddStreamModal` は URL の貼り付けが主用途（プレースホルダも「URL貼付け or 名前入力」）
なのに、貼り付けだけがキーボード操作に依存している。マウスだけで完結しない。

`navigator.clipboard.readText()` でクリップボードから直接入れる。

対象は2箇所:

- 単一入力の `input-row`（`add-btn` の隣、`ClipboardPaste` アイコン）
- まとめて追加の `textarea`（複数行・共有コードの貼り付けもここ）

**設計思想7「機能を足すより操作を減らす」に沿う変更**。ボタンが増えるが、
Ctrl+V → Enter の2アクションが1クリックになるので操作は減る。

採用した挙動:

- 単一入力は**入力欄に入れるだけ**（追加までは走らせない。誤爆を避ける）。
  複数行が入っていても先頭行だけを使う
- まとめて追加は既存の入力に**行を足す**（上書きしない）
- 読み取り失敗（権限拒否・非対応）は握りつぶさず、それぞれの欄の下に
  「Ctrl+V で貼り付けてください」と出す

### 4. 配信枠のレイアウトカスタマイズ（難課題・構想が未確定）

**これが実装できればこのアプリの機能はほぼ完成する**、というのがユーザーの認識。

現状は `calcOptimalGrid()` が枠数から等分グリッドを決めるのみで、
「この枠だけ大きく見たい」ができない。

**過去に実装を試みてエラーが多発し断念した経緯がある。** 構想の段階で二案あり、未決:

- **案A: テンプレート選択** — 何パターンかのレイアウトを用意して選ばせる。
  実装が単純で壊れにくいが自由度は低い
- **案B: 自由リサイズ** — 枠の境界をマウスでドラッグし、他の枠が動的に追従する。
  自由度は最大だが、過去に失敗したのはおそらくこちら

**着手前に必ず確認すること**: レイアウト変更は DOM 構造を触るため、
設計思想4（iframe を壊さない）と正面衝突する。並べ替えで採った
「DOM 順序は `domSeq` で固定し、見た目は CSS だけで変える」原則を外れた瞬間に
全枠がリロードされる。**CSS Grid の `grid-template-areas` / `grid-column` /
`grid-row` を差し替えるだけで表現できる範囲に収まるか**が実現可能性の分かれ目。
案A のほうがこの制約を守りやすい。

同じ理由で未解決の「枠を拡大／復帰すると全枠がリロードされる」は本課題と根が同じ。
先にそちらを CSS だけで解けるか試すのが、案B の実現可能性を測る安価な予備調査になる。

## 機能・UX

### お気に入りフォルダへの移動 UX
ドラッグでのフォルダ間移動は操作しにくい（`tasks/lessons.md` 参照）。
Ctrl+クリック選択＋アクションバーでの一括移動は実装済みなので、
ドラッグ移動を廃止するか、視覚的フィードバックを強化するかを決める。

### ShareModal の読み込みが無警告で全置換
お気に入りと履歴を確認なしに丸ごと上書きする。確認ダイアログか、
「マージ / 置換」の選択が欲しい。

### エラー表示が `alert()`
`ShareModal.tsx` の読み込み失敗のみ `alert()`。他はインライン表示なので浮いている。
`navigator.clipboard.writeText` の失敗も握りつぶしている。

### モーダルにフォーカストラップがない
`role="dialog"` / `aria-modal` もなし。Tab で背面のボタンに抜ける。

### Escape ハンドラの二重登録
`useKeyboardShortcuts`（モーダルを閉じる）と `StreamSidePanel`（選択解除）が
両方 window に `keydown` を張っており、同時に反応する。

### localStorage への書き込みが冗長
`activeStreams` は `streams` の全変更で `JSON.stringify` される。
枠数が多いとメインスレッドを細かく塞ぐのでデバウンス（200ms程度）を検討。

### メタ情報
`index.html` の `<title>` が `multistream-app`、favicon が `vite.svg` のまま、`lang="en"`。

### 枠を拡大／復帰すると全枠がリロードされる
ダブルクリックでの拡大は `StreamGrid` が別のツリーを返すため、対象以外の枠が
すべてアンマウントされる。復帰時に全枠が再読み込みになる。
グリッドの並べ替え（`domSeq` 方式）と同じく、DOM を維持したまま
CSS で見た目だけ切り替えられないか検討する。
